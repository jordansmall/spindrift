The default for gate-discovered work is report, don't fix. When step 3's
failure is proven pre-existing on the base — the REVIEW section's own
clean-checkout proof, not a guess — name it plainly in the outcome note
and, when the run opens one, the PR body, then leave the change out of the
landing: no Filer is provisioned this run, so those are where a human finds
it. A tree the reviewer approved is what lands; a pre-existing failure
belongs to whichever branch introduced it, not to this one to absorb
silently.
